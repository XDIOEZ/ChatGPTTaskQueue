### v0.49.59：任务完成后安全释放 AI 创建的聊天标签

```powershell
node skills/gpt-queue-agent-team/team.cjs finish --run <运行ID> --verified

node skills/gpt-queue-agent-team/team.cjs status --run <运行ID>
```

- **防积压和断线恢复**：每轮限制检查数量、轮转释放目标，避免大量标签阻塞队列；MV3 重启后根据持久任务归属与完成日志继续安全核对。旧版本没有登记来源的标签不会被自动关闭。

### v0.49.58：长任务压力测试与队列自恢复

- 多智能体长流程压力测试暴露了**浏览器标签消息请求无超时、远程调度 `running` 持续锁住**的问题：一条 `CQ_REMOTE_EXECUTE` 或标签读取 Promise 若一直不返回，后续 30 秒调度轮询与扩展目标心跳都不能正常运行，Skill 按在线门槛安全停用。

```powershell
node remote-bridge.cjs cancel-unclaimed --json "C:\path\to\ids.json"
node remote-bridge.cjs quarantine-uncertain --json "C:\path\to\ids.json"
```

  其中 JSON 是 UUID 字符串数组。`cancel-unclaimed` **仅取消 pending、从未领取（attempts=0）**的任务；已领取、已发送、已完成严格拒绝取消。`quarantine-uncertain` **仅隔离租约已经过期、曾领取但仍无回执**的任务，标记 `review_required` 并停用自动重试，不声称此前未发送。所有修改使用原有本机 Bearer token 接口，不允许网页跨域调用；旧版桥接器运行时需重启服务以启用新指令。
- 新增无法返回的浏览器 RPC、读取超时的真实调度锁模拟回归、取消/隔离权限与终态检查。测试创建的旧队列任务仍需按实际已发送/未发送状态人工核对；勿删除状态不明的真实工作消息。
- 此版升级后在 Edge `edge://extensions` 重新加载扩展、刷新测试对话，再运行 `node skills/gpt-queue-agent-team/team.cjs doctor`；磁盘版本与在线扩展版本不一致时 Skill 会安全拒绝继续协作。

- 首次运行：安装 Node.js 18+，在本目录运行 `node remote-bridge.cjs install`（启动仅绑定 `127.0.0.1:43578` 的服务并注册当前 Windows 用户登录自启动）；之后在 Edge 的 `edge://extensions` 或 Chrome 的 `chrome://extensions` 重新加载本扩展，并刷新 ChatGPT 标签页。桥接器自动绑定首次接入的扩展 ID；如重新安装导致扩展 ID 改变，手动运行 `node remote-bridge.cjs reset-pairing` 后重启桥接器连接。

- 不自动点击 ChatGPT 的「重试」，不覆盖草稿，不绕过用户主动停止。网页仍显示停止生成、语音按钮未就绪时保持等待，无法代替 ChatGPT 修复服务端故障。
- 增加原生超时 DOM 回归，覆盖失败隔离、旧错误提示不影响下一轮、原文误报、下一条续发和主动停止保护。

### v0.49.5：修复同项目接力新建对话时的地址不一致

### 自动上下文接力（v0.49.1）

- 打开 **ChatGPT 原生项目中的已有对话**，在插件的 **自动 → 高级设置** 中开启「自动上下文接力」，设置 60 或 120 分钟等间隔（5～1440 分钟）。默认关闭，设置仅作用于当前对话。
- **立即接力（无需队列或定时开关）**：队列底部工具栏「接力」按钮可在队列为空时手动总结当前对话，并在同一原生项目的新对话继续。当前回复尚在生成时先等其结束；连续点击不会生成多个总结。不在原生项目、当前对话/队列已暂停或交接未完成时按钮不可用。与此不同，**定时接力**仍仅在有待发送任务时启动，避免空队列反复跳转。
- **悬停查看对话时长**：鼠标停在「接力」按钮上可看到当前对话已持续多久、时间来源与接力状态，分钟数会随时间刷新。优先采用 ChatGPT 页面首条用户消息明确提供的时间；如果页面没有可靠消息时间，改为显示「插件已记录至少多久」，并持久化首次记录时间供下次查看。对于老聊天无法推断官方创建时间，提示会明确说明实际开始可能更早。不读取私有接口，也不发送额外的对话消息。
- 到期时只有队列仍有待发送任务才启动；先等待正在执行的回复完成，再由插件发送专用总结提示词。插件确认请求之后生成的新助手回复已经完整结束后，直接以该回复正文作为交接文档，不再识别首尾标记。若无法确认新回复、总结长度不合法或接力期间插入额外用户消息，则不迁移原队列。
- 插件通过原生项目路径（例如 `/g/g-p-…/c/…`）识别项目；同标签导航至相同项目的 `/project` 新对话入口。若 ChatGPT 改变了页面路由、尚未创建真实对话、或无法验证同一个项目，则绝不把任务迁往普通对话。
- 新对话首次收到交接记录并完成回复后，插件在同一次持久化写入中迁移旧队列的剩余任务、图片引用、定时规则、本对话限速和发送冷却等设置。新对话的下一次接力计时从迁移完成后重新开始。
- 跨对话交接时保持旧队列锁定；旧队列仅在迁移确认成功后清空。失败时可返回旧对话，通过队列上方的失败提示取消交接（或打开「自动 → 高级设置」）；若新对话的消息已经发出且状态不确定，会拒绝自动取消以防重复执行。
- 计时取决于扩展后台闹钟和浏览器运行状态，可能因休眠延后。使用原生项目之外的聊天（普通对话或自定义 GPT）不能启用此功能。每次总结会消耗一次正常 ChatGPT 对话请求；时间规则不能保证在上下文耗尽前及时交接。
# ChatGPT 自动对话队列（Chrome / Edge）

Manifest V3 独立浏览器插件。直接把队列嵌入 ChatGPT 原生输入框上方。无需账号令牌、私有 API 或远程服务。

这是一个独立的第三方工具，与 OpenAI、ChatGPT、Microsoft 无官方关联。插件只在 `chatgpt.com`（及兼容的 `chat.openai.com`）页面运行，队列数据保存在浏览器 `chrome.storage.local`，图片原图保存在扩展自己的 IndexedDB 中，插件不会将队列数据上传到 GitHub 或其他服务。轮到发送图片任务时，图片会通过 ChatGPT 原生附件上传入口发往 ChatGPT。网页结构变化时，自动发送功能可能需要更新。

## 核心规则（v0.47.0）

**同一条消息只使用 ChatGPT 右下角的 Voice Mode 波形按钮确认完成。**

1. 普通队列选取第一条 `pending` 待办，调用 ChatGPT 原生发送按钮。
2. **点击发送后立刻**持久化成 `waiting`。不等待新用户气泡、助手文字、消息数变化，也没有额外的「发送结果确认」步骤。
3. 等 Voice Mode 按钮（例如 `Start Voice`）重新出现并稳定 **至少 1.7 秒**，同时编辑框为空、原生停止生成按钮已消失，就删除这一条；如果本对话设了发送冷却，还会等待设定时长，才领取下一条。
4. 语音波形按钮不等于旁边的麦克风/听写按钮（`Start dictation`）；后者**绝不能触发接力**。

这个判断依赖 ChatGPT 当前网页 DOM。插件不使用回复正文检测完成，因此图片回复、被虚拟化的消息也能继续；但网页更新、语音模式不可用或未被识别时，会继续等待而非盲目重发。**如果按钮在实际处理完成前错误出现，可能提前推进**，因此仍保留 1.7 秒稳定检测和输入框/停止按钮保护。

## v0.19.0：检测插件版本升级后自动刷新 ChatGPT 页面

- **只监听扩展自身版本变化**：当 Edge/Chrome 通过扩展更新事件报告版本从旧号升级到新号（例如 v0.18.0 → v0.19.0）时，自动对当前已经打开的 `chatgpt.com` 和 `chat.openai.com` 页面安排刷新。不是监测 ChatGPT 网页更新，也不会在首次安装、浏览器自身升级或重复加载同一插件版本时触发。
- **正常页面自动刷新、无需手动逐个 F5**：后台通过具有网站权限的 `chrome.scripting.executeScript` 检查已打开网页，再通过 `chrome.tabs.reload` 刷新页面，重新注入新版本内容脚本。检查多个标签页时并行执行，刷新前至少间隔 1.8 秒确认两次页面仍安全。
- **避免打断生成和丢弃草稿**：输入框内有未发送的文字或附件、图片正在上传、ChatGPT 正在生成回复、插件「图文/自动」草稿中有未保存文字或图片、插件设置有未保存改动时，暂不刷新。若后台记录仍有发送中/等待回复/引导中的任务，还要求网页原生 Voice Mode 按钮已恢复才允许刷新。安全条件满足后会在后续检查中自动完成刷新。
- **跨服务工作线程延续**：待刷新的标签 ID 和目标插件版本暂存在扩展 `chrome.storage.session` 中，后台服务工作线程睡眠或重启不会丢失待刷新计划；每分钟的后台调度及页面重新加载会触发重试。已经刷新成功的页面不会循环刷新；已关闭、离开 ChatGPT 或已被浏览器丢弃的标签不会被主动唤醒。
- **适用范围**：需要浏览器已经识别并加载了升级后的插件版本（例如扩展商店自动更新，或开发者模式重新加载一个**版本号已改变**的解压插件）。单纯修改本地源文件、但不让浏览器重新加载插件，并不会产生扩展更新事件。新增的 `scripting` 权限只用于检查已获授权的 ChatGPT 标签页是否可以安全刷新。

## v0.18.0：草稿与本地存储一致性保护

- **保存期间的新输入不再丢失**：保存「图文」任务或创建/编辑自动任务时，即使用户继续修改文字、图片、触发间隔等内容，旧请求成功后也只确认已提交的版本，不会清空或覆盖之后输入的草稿。新编辑保留在表单里，可以再次主动提交。
- **对话切换保护**：若异步保存期间 ChatGPT 导航到了另一个对话，插件不再把旧对话的响应写回当前对话界面。原生 Enter 入队在保存后也会重新核对输入框、附件和对话 URL；发生变化时保留现有输入内容，提示人工确认，而不是自动移除新附件或清空新草稿。
- **提交标识绑定实际内容**：同一请求 ID 的安全重试现在附带按内容计算的 SHA-256 指纹；若意外将同一 ID 用于不同提示词、图片或创建操作，会明确拒绝冲突，而不是静默吞掉不同的任务。大图片按张计算指纹，避免一次性复制多张原图造成额外内存压力。旧版未含指纹的短期记录仍沿用不重发保护。
- **本地图片写入回滚**：如果图片已保存到 IndexedDB，但队列任务、编辑结果或规则未能成功写入 `chrome.storage.local`，会重新核对真实存档，只清除没有被任何已保存任务引用的本次新增原图。即使浏览器实际已写入数据却返回错误，也不会误删已有队列引用的图片；无法确认存档状态时优先保留原图。
- **不改变已有调度**：原有按对话公平轮询、数量补队限速、暂停恢复、发送确认机制、旧版数据和图文备份格式均保持兼容。SHA-256 指纹只存本地去重记录，不包含提示词或图片正文；它用于区分误复用请求，不是云同步或数字签名。

## v0.17.0：定时公平轮询和重复提交保护

- **多个按时间规则公平补队**：同一对话存在 A、B、C 等多个已到期的定时规则、队列仅剩少量空位时，按上次成功补入的位置继续轮流尝试，避免前面的规则一直抢到唯一空位。游标按对话持久化，插件刷新或服务工作线程重启后仍保持公平。规则各自的间隔、下一次到期时间和循环次数不变；未到期、已停用、执行次数耗尽的规则继续跳过。
- **图文入队/自动任务创建防双击**：保存过程中按钮显示忙碌状态，连续点击不会再触发多次提交。原生输入框的 Enter 入队也使用提交标识，已保存但确认响应丢失时可安全重试。
- **提交幂等**：插件后台对每个对话分别保存近期提交标识；同一标识重复到达时返回已有成功结果而不重新保存图片、队列任务或自动规则，即使原条目随后发送完成、删除或后台重新启动。新一轮主动操作使用新的标识，因此允许用户主动连续提交相同文字。
- 为控制本地存储占用，提交标识最多保留最近 **128** 个、最长 **24 小时**。这保护常见的双击和网络响应丢失，**不是跨无限时间的严格恰好一次保证**；旧版不带标识的消息仍兼容。

## v0.16.0：后台标签恢复和定时调度隔离

- **被丢弃的标签不再误判为在线**：对已开启「自动恢复标签」的对话，浏览器若将对应标签页 *discard*（丢弃、卸载）但尚未关闭，插件优先尝试在原标签上通过浏览器原生重载恢复，不额外创建重复标签，也不切换窗口焦点。
- **优先复用正常标签**：同一对话在其他正常加载的标签中仍然打开时，插件将调度所有权转交给可用页面；不会唤醒无效的旧标签，也不会允许旧标签继续领取后续任务。如果原标签无法重载，才尝试新开一个后台页面。
- **慢网络保护**：新开的标签如果还在浏览器 `pendingUrl` 导航中，不会因每分钟的后台闹钟而反复创建新标签；在 URL 尚不可读时采用短暂退避。若标签已经明确跳到其他对话，则可再次尝试恢复正确对话。
- **单对话失败不拖垮全局**：某个标签的查询、重载或创建出错，只影响该对话本轮页面恢复，不会使其他对话的定时入队失效，也不会丢弃已到期的队列任务。连续失败最多每 10 分钟写一次诊断事件；成功恢复、重新打开或更换所有权也会记录到各自对话的运行日志。
- v0.49.36 起，默认开启的「后台队列防丢弃」也会恢复已存在且归属明确的被卸载标签；「关闭后自动重新打开」只控制标签已关闭时是否重新创建。关闭后台保护且未开启自动重开时，不自动恢复。恢复不保证解除 Edge 休眠/冻结、网络断开或电脑休眠，且遵循队列原有的发送锁和不重复发送保护。

## v0.15.0：异常重启后的任务状态一致性保护

- **自动检查队列运行锁**：页面初始化、尝试领取下一条待办以及后台每分钟检查时，核对活动任务 ID 与实际任务状态是否一致，并检查发送/引导时间戳。若发现活动锁丢失、指向错误任务、时间戳无效或存在孤立的发送中/引导中任务，会将无法确认送达的记录标记为「需要检查」，暂停该对话自动发送。不会将这些任务直接改成待发送，也不会自动重新发送。
- **人工核对后恢复**：在网页聊天记录中核对异常消息后，点击队列提示中的「核对后跳过」。有多条异常中断记录时，需要逐条核对；处理第一条不会提前解除暂停。没有待核对的错误记录时可通过「核对后继续」恢复，后面的正常待办仍保持原顺序。
- **区别原生停止与异常隔离**：ChatGPT 原生「继续生成」只解除用户主动点击 Stop 所产生的暂停；不能绕过状态不一致的安全隔离。语音按钮自动恢复机制同样不会解除这类异常暂停。正常的旧版 `waiting` 记录（有有效的 `sentAt`）仍可按原语音完成检测收尾。
- **诊断日志修正**：如果某次 `CLAIM` 只是修复异常锁，并没有真正领取任务，不再误写“领取待发送任务”的日志。状态隔离事件会记录在当前对话运行日志里，不包含完整提示词。

## v0.14.0：图文备份完整性与恢复前预检

- **逐张 SHA-256 校验**：新导出的备份会为每张原图保存内容摘要。恢复时后台重新计算摘要，哪怕损坏图片仍具有相同文件名、类型和字节数，只要内容与备份摘要不一致就拒绝写入暂存区，不会生成可能误发的队列任务。
- **恢复之前先校验任务清单**：在上传任何原图前检查原对话、任务状态、自动规则、提示词长度、循环次数、数量阈值和图片引用是否完整。清单不合法则立即报错，避免花时间上传几十 MB 图片后才发现无法恢复。
- **发送和导出前验证本地原图**：原图不仅要能按 ID 找到，还需检查文件格式标识、实际解码大小、元数据及缩略图格式。发现 IndexedDB 里的原图被截断或损坏时拒绝发送/导出，避免只发送文本。
- **兼容旧 JSON**：v0.11～v0.13 已导出的 JSON 文件没有 SHA-256 也可以恢复，仍须通过原有图片格式及大小验证；新导出格式保持版本 1，只增加可选 `sha256` 字段。摘要用于检查意外损坏，**不是数字签名、加密或防恶意篡改的认证机制**；持有 JSON 的人仍能修改数据及重算摘要。

## v0.13.0：大型图文备份改为分段传输

- **导出不再一次传输整份备份**：先读取当前对话任务/规则清单，检查引用图片是否存在，再逐张从 IndexedDB 取出原图，最后在浏览器本地组装为完整 JSON 文件。每张原图独立校验文件名、类型、大小和图片 ID；任何一张丢失或对话切换时都不生成不完整的备份。备份文件格式仍与 v0.11/v0.12 的 JSON 兼容。
- **恢复采用两阶段提交**：选择 JSON 文件并确认后，先发送轻量清单，后台生成临时恢复令牌，再逐张验证并暂存图片。仅在所有图片确认存在、规则和待办验证全部通过时才写入当前对话队列。中途失败或取消会清理暂存记录；不会覆盖现有任务，也不会自动发送旧任务。
- **暂存区有安全隔离**：恢复令牌绑定当前对话和标签，其他对话不能读写。15 分钟后过期自动清理；如果插件后台服务被系统重启，恢复会话会失效，需要重新选择备份文件，未提交的临时原图会在启动清理时回收。尚未完成的临时图片不会被其他队列的正常图片清理误删。
- 单张原图仍不超过 8 MB，完整备份文件上限仍为 **60 MB**。分段传输解决大型消息问题，但浏览器仍需要在本地处理最终的 JSON 文件；不能保证所有平台都能处理极端大型备份。原有备份文件依然可以导入。

## v0.12.0：图文传输与存档保护

- **大图片逐张传输**：队列最多允许 4 张图片、每张 8 MB。此前发送前一次读取全部原图，极端情况下会产生巨大的扩展消息。现在改为一张一张从 IndexedDB 读取并验证任务引用、格式、文件名和实际大小；全部原图取齐后才交给 ChatGPT 原生附件组件。任意图片缺失或不一致时都不会点击发送，保持失败保护。仍兼容已经打开的旧内容脚本使用的批量图片接口。
- **当前对话图片自检**：打开底部「设置」，点击「检查本对话图片存档」，可检查当前对话队列和自动规则引用的原图**是否存在**，并统计缺失图片影响的任务数。自检不清除数据、不改变队列或发送状态，也不读取图像正文；原图存在不代表图片一定能在 ChatGPT 上传成功。
- **异常存档拒绝覆盖**：如果本地队列存档来自未来版本、关键字段缺失或结构损坏，扩展会拒绝自动重建空队列，启动检查也不会触发原图清理，避免更新/降级时误丢任务和图片。需要使用兼容版本或先人工处理备份，插件不会擅自改写存档。

## 后台队列保护

- **设置 → 后台队列防丢弃**，默认开启，所有对话共用此设置。有队列任务、启用的自动规则或接力时，使用浏览器原生 `chrome.tabs.update({autoDiscardable:false})` 阻止所属标签页被浏览器自动丢弃；接力进入项目页、新对话开场及地址生成时连续保护。已被卸载的所属标签会在原标签恢复，不依赖关闭后重开开关。
- 队列清空且所有自动规则停用后，恢复插件修改前的标签页设置；原本就由浏览器或其他工具保护的标签页不会被强行恢复成可丢弃。页面切换到其他网站或标签关闭时也释放保护。每分钟后台检查并在需要时重新应用。
- 后台定时器每分钟向仍存在的队列页面发送一次唤醒消息，尝试补偿后台 JavaScript 定时器被限制后的队列接力，不切换标签或抢夺窗口焦点。
- 在「自动」区域可以单独给当前对话开启关闭/丢弃标签后的自动恢复（默认关闭）；开启后也不会强制抢占前台，且不会让一个无法恢复的对话阻止其他会话按时入队。
- **重要限制：** 阻止 *discard* 不能阻止 *freeze/sleep*，冻结后浏览器不运行页面定时器，插件也不能强制解冻或保证消息即时发送；浏览器关闭、电脑休眠、断网期间同样不能持续运行。不要通过播放静音音频或强制切换前台来规避浏览器机制。
- 使用 Microsoft Edge 时，建议打开 **设置 → 系统和性能 → 性能 → 始终保持这些网站处于活动状态**，添加 `https://chatgpt.com`；若使用 `chat.openai.com`，也将其加入列表。这样可以同时排除 Edge 的休眠策略影响。

### ChatGPT 出错后自动接力（v0.6.2）

- ChatGPT 显示「消息传输超时，请重试」等错误后，如果插件因技术异常记录了 `failure`、`timeout`、`uncertain` 或 `steer_unconfirmed` 暂停，**原生 Voice Mode 波形按钮重新出现并稳定至少 1.7 秒后，会自动解除这一技术暂停**。
- 技术故障中已经尝试发送、但可能未成功的那条消息会保留为「需要检查」的错误记录；**绝不会重新发送该条**。后面的普通待办和定时入队任务按队列顺序继续执行。
- **用户自己点击「停止生成」不会被自动解除暂停**，未绑定的旧版导入暂停同样保留。
- 输入框有草稿、显示停止生成按钮、语音按钮没有恢复或识别到的只是听写麦克风时，不进行自动恢复。已存储的旧式技术错误也会在检测到语音按钮后恢复。

## 自动入队：定时 / 按队列数量

- 点击工具条 **自动**，使用 **当前自动任务** 和 **＋ 创建任务** 两个独立页面切换。创建区不再与已有任务列表混在一起；列表中仍可启停、编辑、删除。
- 每个对话的自动入队规则相互独立，可以选择 **按时间** 或 **按队列数量** 两种触发方式；两种模式都只负责入队，不直接发送。
- **按时间**：设置间隔（分钟），倒计时每秒刷新。
- 到时间就新增**一条普通 `pending` 待办**。即使 ChatGPT 还没回答完，定时器也照常入队。**定时器不负责发送、等待回复或确认完成**。
- **按队列数量**：设置阈值（例如 3 条）。当当前对话的待执行数量低于 3 时，自动补入普通待办，逐步维持至少 3 条；数量足够时不再补充。已领取、发送中、等待回复和引导中的任务也计入数量。
- **当前对话数量补队限速（v0.9.6）**：打开「自动」面板下方的「数量补队频率限制」，可以为**当前对话单独**启用/停用，并设置「每 1～1440 分钟，最多自动补入 1～200 条」。例如 10 分钟最多 3 条，限额用完后等最早一次自动补队满 10 分钟才恢复一个名额，采用滚动窗口而不是整点清零。
- 本对话下所有「按队列数量」的自动规则**共用同一个入队额度**，仍按轮询顺序公平补入。只有成功加入队列的数量触发任务才占额度；因队列已满或达到上限而暂缓的任务不消耗次数，也不会丢失规则。原有队列数量上限、各规则的循环次数和数量阈值仍然生效。
- 这个限速**默认关闭**，保存到各自的对话数据中，切换对话及重新打开浏览器后不会互相覆盖；已用额度及补队记录也会保存，不会因为刷新页面重置。手动入队、图文入队、按时间触发的自动入队均不受此数量检测限速影响。界面会显示已用额度和下一个名额的倒计时；页面打开时自动检查，后台每分钟兜底检查。
- **多任务轮询（v0.9.2）**：同一对话有多个「按队列数量」自动任务时，按照 A → B → C → A 的顺序检查和补队。轮询位置保存在对话数据中，刷新网页或插件后台重启也不会始终从第一项开始；每轮每条符合条件的规则最多补一条，队列满则等待空位。停用、达到循环次数上限、未达到自身触发条件的规则会跳过。
- 各自动任务仍遵循自己设置的数量阈值。例如队列有 3 条时，「少于 2 条」的规则不会参与补队；若需要所有规则均匀参与，可把它们设置为相同阈值。
- 任务完成、删除或规则新增时立刻检查数量；已打开的页面还会定期检查，浏览器后台每分钟兜底检查。数量模式不依赖倒计时到点才触发。
- 循环次数 `-1`：无限次入队；`0`：入队一次；`N`（正整数）：一共入队 `N+1` 次。
- 右侧 **设置** 按钮可调整队列数量上限（1～200，默认 **100**，考虑浏览器本地存储容量）。该设置对所有对话生效，但每个对话分别计数；手动和两种自动入队模式共用上限。降低上限不会删除旧任务。数量模式阈值不可高于保存规则时的上限。
- **新建自动任务默认值（v0.9.3）**：在「设置」中可调整默认循环间隔（1～525600 分钟，初始 **30 分钟**）和默认循环次数（`-1` 无限、`0` 单次、`N` 再重复 N 次，初始 **-1**），与队列上限一起保存。以后在「自动 → ＋ 创建任务」中新建时自动带入，仍可针对单条任务修改。
- 默认循环间隔仅用于「按时间」模式，「按队列数量」模式不会因为默认间隔而延迟；默认循环次数对两种模式都适用。全局默认值在所有对话中共享，修改它不会更改任何已经保存的自动任务、剩余倒计时或执行次数。
- 同一规则允许产生多条待办；每次检查、每条规则最多新增一条，直到达到数量阈值或队列上限。「按时间」模式保持独立倒计时，不参与数量规则的轮询，队列满时保留到期机会，空出位置后补入一条。
- 浏览器睡眠、关闭期间无法实际发送；恢复时不会一次补入大量错过周期的任务。
- 旧版 `deferred` 定时状态可迁移成一条普通待办，已完成的任务不会重发。

## 图文队列和图片保存

- 点击工具条 **图文**，在独立输入区填写提示词，点击「添加图片」、直接粘贴截图或把图片拖到上传区域，再点「加入队列」。支持只有图片而没有文字的任务。
- **原生输入框支持图片入队（v0.49.70）**：可以在 ChatGPT 原生输入框里选择 PNG、JPEG、WebP、GIF 图片后，**点击插件底部「入队」按钮**保存到队列。Enter 与 Ctrl/Cmd+Enter 均为直接发送，不负责图片入队。插件会捕获原生文件选择事件、保存原图，支持文字＋图片、仅图片、多张图片；成功保存后尝试调用原生附件上的「移除」按钮，再清空提示词，避免重复发送。
- **图片优先保证不丢失**：如果插件没有捕获到真正的 `File` 对象（例如插件启动前已选图、网页更新导致附件结构变化）、图片仍在上传、图片预览与原图数量不符，**不允许只将文字入队**，草稿和附件仍留在原处。若入队成功后原生附件无法自动清除，会提示你先手动清空，再继续队列。当前不支持任意非图片文件。
- **自动任务的创建/编辑界面**也可以附加图片；按时间或数量生成的待办会复用同一份已保存的图片。
- 支持 PNG、JPEG、WebP、GIF，每条任务最多 **4 张**，每张不超过 **8 MB**。可以在任务编辑界面添加/移除图片，队列列表展示缩略图，刷新 ChatGPT 页面后仍可恢复。
- 队列状态仅存图片引用和缩略图，完整图片单独保存在浏览器扩展的 IndexedDB；删除最后一个引用后清理原图。**清除扩展存储或卸载插件会丢失队列图片。**
- 轮到任务时，插件逐张读取原图并验证任务引用后，尝试将图片装载到 ChatGPT 原生附件控件，**只有检测到附件预览和可用的发送按钮后才发送**。上传控件改变、图片缺失或无法确认附件时，会暂停并提示人工检查，绝不只发送文字。由于依赖 ChatGPT 网页 DOM，此过程无法保证适用于每次网页更新。
- 含图片的队列任务暂不支持「引导」提前发送；`Ctrl+Enter` 仍然不能经由插件自动处理原生附件，如需即时发送带附件消息可以直接点击 ChatGPT 原生发送箭头。

## 快捷键和队列

队列操作区已移至面板底部：上方只显示队列数量、运行状态与下次自动入队时间；下方集中放置「入队」「图文」「自动」「设置」和展开/收起按钮，快捷键提示靠左。收起队列时底部操作按钮仍然可用，点击功能入口可直接打开相应面板。

**手动调整高度（v0.9.5）**：展开队列后，拖动任务列表底部的「拖动调整高度」横条可以上下改变可见高度，任务过多时在列表内部滚动；列表为空时也能调整。松开鼠标/触屏时自动保存高度，对所有对话生效，刷新页面、切换对话仍会保留。**双击调节条**或用键盘选中它按 `Home`，可恢复自动高度；`↑/↓` 可微调（按住 `Shift` 调整幅度更大）。高度限制为 **72～900 像素**，同时会根据当前浏览器窗口高度自动收紧，避免超出屏幕。调整高度不会改变任务排序或发送状态。

| 操作 | 效果 |
|---|---|
| `Enter` | **ChatGPT 原生直接发送**，无论新聊天、旧聊天或当前队列是否为空 |
| `Ctrl+Enter` / `Cmd+Enter` | 通过原生发送箭头尝试即时发送/引导，不添加普通待办 |
| `Shift+Enter` | 换行 |
| 「＋ 入队」 | 将原生输入框的文字和可读取的图片一起入队，允许纯图片 |
| 「暂停 / 继续」 | 暂停/恢复**当前对话的自动发送接力**，已在运行的任务不强制中断，自动规则仍继续入队 |
| 「图文」 | 在插件里独立创建带图片的队列任务，支持粘贴或拖入图片 |
| 「自动」 | 在创建区和当前自动任务列表之间切换 |
| 队列项「置顶」 | 将指定待发送任务移动到待发送队首，不抢占已发送或正在等待的任务 |
| 拖动队列条目 | 按住待发送条目拖动，在另一个待发送条目的上半部或下半部松手，调整发送顺序 |
| 队列项「引导」 | 尝试提前发送选中的待办；若网页不允许，原任务保留 |

队列待发送任务可整条拖动，拖动时显示落点指示线；不再提供原来的「上移 / 下移」两个按钮。置顶是**立即调整排队顺序**，不是永久固定，也不会调用 ChatGPT 发送按钮。执行中、等待回复、引导中以及历史错误任务不会被拖动，也不能成为拖动目标；调整任务顺序不会挪动这些任务。新顺序自动保存，刷新和切换对话后仍有效。

**快捷键规则（v0.49.70）：** 普通 Enter 完全交给 ChatGPT 原生编辑框发送；Ctrl/Cmd+Enter 通过原生发送按钮即时发送或在生成中进行即时引导。**所有手动入队请点击插件底部「＋ 入队」或图文编辑器「加入队列」按钮**，不再使用键盘快捷键自动入队；插件内部自动规则、收藏和远程队列 API 不变。Shift+Enter 换行，中文输入法与斜杠候选菜单保留网页原生行为，输入附件不完整时按按钮入队仍会拒绝丢图只保存文字。

**手动暂停接力（v0.10.0）：** 底部「暂停」仅暂停当前对话领取下一条待发送任务；当前已经发送/等待回复的消息继续按原机制确认完成，定时或数量规则仍可往队列里补充待办。点击「继续」恢复，不会自动解除原生 Stop 或技术故障引起的队列暂停。这个状态独立保存在各对话中，切换聊天或重新打开浏览器后保持。

## 运行日志与备份恢复（v0.11.0）

- 打开插件底部「设置」，在最下方查看**本对话运行日志**。每个对话保留最近 **80** 条事件，记录手动/自动入队、发送、完成、异常、停止、继续和规则编辑。只记录事件、时间与短任务 ID，**不另外存储提示词、错误原文或图片正文**；可只清除日志，不影响任务。同一区域还可以检测当前对话缺失的图片引用。
- 点「导出本对话完整备份」会生成一个 JSON 文件，其中包含当前对话的任务与自动规则及**图片原图**（从扩展 IndexedDB 逐张读取）。此备份只针对任务和规则，**不包含其他对话、全局默认设置或过往日志记录**。若引用图片缺失、文件太大（上限 **60 MB**）、任务/图片过多，拒绝生成不可完整恢复的备份。
- **备份包含用户提示词和完整图片，是未加密的敏感文件。** 请只保存到自己可信任的位置，不要公开分享。此功能完全在浏览器本地执行，不会上传到第三方备份服务。
- 「选择 JSON 备份恢复」需要用户确认，且**只能恢复到原对话的空任务/空规则列表**，禁止覆盖已有或运行中的队列。图片先暂存，全部确认后才提交；恢复时使用新 ID 重新保存图片，保持文本与图片引用一致；所有规则默认停用且从零重新计数，补队限速历史重新计算，自动发送暂停，用户核对后手动启用规则或点「继续」。
- 备份中的发送中、等待回复、引导或失败记录都**不会自动重发**，恢复后标记为「需要检查」；只有备份时确认为 `pending` 的待办在用户手动继续后才可能执行。恢复不会自动打开关闭的标签，也不会立即调用 ChatGPT 发送按钮。
- 这是一种**按对话的手动备份**，不是自动云同步。Chrome/Edge 扩展更新与网页 DOM 更新仍可能影响实际发送体验；建议更新前先导出关键对话。

队列任务完成后立即从列表删除。切换 ChatGPT 对话时会自动显示各自的队列和定时器，不允许跨对话串发。原生「停止生成」代表用户暂停整个当前对话队列，恢复聊天后才继续。

**安全边界：** 原生输入框快捷键支持文本及能取得真实文件对象的图片；无法取得原图、图片尚在上传或发现其他文件类型时不会只保存文字。插件不会覆盖用户未发送的草稿；已点击发送的内容不自动重试。超时或状态不确定时保留人工核对能力。引导功能还需要核对原生用户消息，防止选中任务提前发送后再次被队列发送，不属于普通队列的完成检测。

## Edge 标签红点

后台标签页完成一轮新回复时，在标签标题前显示 `🔴`；切回标签自动消失。不弹窗、不跳转。因 Edge 不开放任意设置标签原生未读点的接口，采用修改页面标题实现；垂直标签栏折叠时可能不明显。

## 安装或更新

1. Edge 打开 `edge://extensions`（Chrome 打开 `chrome://extensions`），开启开发者模式。
2. 在 GitHub 的 **Releases** 下载最新版本 ZIP 并解压；也可以通过仓库右上角的 **Code → Download ZIP** 下载源码并解压。
3. 选择「加载解压缩的扩展」，指定包含 `manifest.json` 的文件夹（不是 ZIP 文件本身）。
4. 已安装旧版则点击扩展的 **刷新**，然后刷新 ChatGPT 网页。
5. 为防止第一次测试时误发送，建议新建对话，用简短提示词测试 3–5 轮。

## 测试

在仓库根目录运行：

```bash
node --test tests/*.test.cjs
node --check content.js
node --check background.js
node --check image-store.js
```

`tests/composer-smoke.html` 可以直接在 Chrome / Edge 本地打开，确认输入框上的布局和快捷键；`backup-dom.test.cjs` 验证日志、图片自检、导出文件与人工确认恢复界面，`background.test.cjs` 覆盖逐张图片读取授权、异常存档保护、安全恢复、会话隔离与日志上限；`native-image-entry-dom.test.cjs` 用真实 Chrome 测试原生选图后按 Enter / 点入队、纯图、多图及原图缺失时的安全拦截；`resize-dom.test.cjs` 测试列表高度拖动、缩放、滚动、收起恢复和键盘操作；`keyboard-dom.test.cjs` 验证发送箭头可用时空队列也只接受 Enter 入队、Ctrl/Cmd+Enter 即时发送、富文本编辑器、输入法及候选菜单保护；`settings-dom.test.cjs` 验证自动任务创建/列表分区、设置面板及手动暂停；`reorder-dom.test.cjs` 验证置顶、整条拖动、落点高亮与禁止拖动正在执行的任务；`image-queue-dom.test.cjs` 验证四图逐张读取、原生附件恢复与缺图阻止发送，`image-store-dom.test.cjs` 使用真实 Chrome IndexedDB 验证图片存储、存在性检查和清理。`message-dom.test.cjs` 和 `voice-button.test.cjs` 验证没有消息气泡/正文时仍凭语音按钮推进队列。`error-recovery-dom.test.cjs` 模拟 ChatGPT 出现传输错误并恢复语音按钮后的自动接力，另外测试覆盖数量触发、队列上限、定时循环、跨对话隔离、引导、红点及用户主动停止。

**自动化测试不等于真实 ChatGPT 登录页验收**，网页实际 DOM 可能更新。浏览器后台标签可能被节能机制延迟调度。
